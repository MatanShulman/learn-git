# t002 — Add automatic tests and CI

**State:** Not started
**Depends on:** t001

## Goal

Add a tiny helper function with tests, and make GitHub run the tests automatically (CI) on every
pull request and every update of `main`.

## Scope

- `package.json` with no dependencies; `npm test` runs the tests (`node --test`).
- `logic.js` with one function, `addOne(n)`. The page loads it as a normal `<script>`.
- `tests/logic.test.js` with tests for `addOne`.
- `.github/workflows/checks.yml`: runs `npm test` on every pull request and every push to `main`.
- `.github/pull_request_template.md`: the PR description template.
- `README.md`: how to run the tests.

## Out of scope

- Any visible change on the page.

## Acceptance criteria

- [ ] `addOne(3)` returns `4`, and `addOne(0)` returns `1`.
- [ ] `addOne("hi")` or `addOne()` doesn't crash: it returns `1`, as if counting from 0.
- [ ] `npm test` passes on Matan's PC.
- [ ] CI runs on the PR and is green on the latest commit.
- [ ] The page still opens by double-click, with no errors in the browser console.
- [ ] `package.json` has no dependencies.

## How to verify

1. `npm test` → all tests pass.
2. `gh pr checks` → the check is green on the latest commit.
3. Double-click `index.html` → F12 → Console: no red errors.

## Evidence

Filled in by the PR that finishes this task: what was checked, the result (passed / failed /
not run) and the PR link.

## 🎓 Learning purpose

**Who drives:** Claude (Matan watches).

**What Matan learns:** what a test is, what CI is, and how a PR shows ✅ or ❌.

**After the merge:**

- Check that CI also ran on `main` and is green.
- Turn on "Require status checks to pass" for `main` (a settings change, with Matan's OK).
  GitHub only lists a check in that setting after it has run once, and it runs for the first time
  in this PR. From t003 on, GitHub refuses to merge a PR with a red check.
- The PR template starts working from the next PR, because GitHub reads it from `main`.

These steps are not in the acceptance criteria because "Done" must be proven before the merge.
