# t008-04 — Write down the full delivery loop

**State:** Not started
**Kind:** Leaf
**Parent:** [t008](t008.md)
**Depends on:** t008-03

## Goal

The steps from "pick a task" to "`main` is healthy after the merge" are written once, in detail,
with who does each step and what counts as passed.

## Scope (draft)

`docs/workflow.md` and `AGENTS.md` describe the full loop:

- Main health with four results: verified / pending / failed / unknown. Pending is not a pass. If
  `main` failed, a separate repair PR comes first.
- A readiness check with a verdict: ready / needs split / design needed / blocked.
- The worker implements and runs the local checks.
- A review by a fresh agent session that didn't write the code; the same worker fixes.
- A PR-readiness review with a verdict: ready / ready with minor follow-ups / not ready.
- Review replies: fixed / disagreed (with the reason) / partly fixed.
- Merge only the exact reviewed commit: `gh pr merge --squash --match-head-commit <SHA>`.
- A short decision and evidence report for each task.
- Planning PRs: a PR that only adds or changes task files and finishes no task. What must be
  true before it is merged (today rule 10 assumes every PR finishes a task).

## Out of scope

- The agent skills (t008-05).
- CI changes and GitHub settings (later tasks).

## Acceptance criteria

Written at the readiness step, before any work starts.

## Evidence

Filled in by the PR that finishes this task.
