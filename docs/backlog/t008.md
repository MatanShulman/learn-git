# t008 — Adopt the full team method

**State:** Not started
**Kind:** Aggregate
**Parent:** —
**Depends on:** nothing

## Goal

The repo's rules, task files, docs and agent skills describe one complete way of working, from
choosing a task to checking `main` after the merge. Every task after t008 (t001–t007) follows it.

## Children

An aggregate has no work of its own: the work is done in its children. Each child is one branch
and one PR.

## Out of scope

- Any change to the page itself (t001–t007).
- CI and automatic checks (t002 and later tasks).
- Changes to GitHub settings, such as required approvals (planned in later tasks).

## Acceptance criteria

- [ ] Every child is `Done`, with its evidence and its merged PR.
- [ ] Read together, `AGENTS.md`, `docs/workflow.md`, the backlog and the skills use the same
      steps, names and states, and don't contradict each other.
- [ ] A fresh agent session that reads only `AGENTS.md` (and the files it links) can say what the
      next step of a task is and who does it.
- [ ] t008 is not marked `Done` while any child is not `Done`.

## How to verify

1. The children table above: every child is `Done` and has a PR link in the backlog index.
2. Read `AGENTS.md`, `docs/workflow.md`, the backlog index and the skills side by side, and list
   any contradiction.
3. Start a fresh agent session, ask "What is the next step for t001, and who does it?", and compare
   the answer with `docs/workflow.md`.

## Evidence

Filled in by the PR that marks t008 `Done`, after the last child is merged: who reviewed the whole,
what was checked, the result (passed / failed / not run) and the PR links of all children.

## 🎓 Learning purpose

**Who drives:** Claude writes the files. Matan types every Git and `gh` command and reviews each PR.

**What Matan learns:**

- How a big piece of work is split into a parent (**Aggregate**) and small children (**Leaf**),
  each one its own PR. The parent is `Done` only when all children are `Done` and the whole has
  been checked together.
- The full team method from Matan's teacher's real project, at small scale, set up before the app
  tasks start ("set up the kitchen before cooking").

**How t008 started:** with a **planning PR** that adds only these task files, so the plan is
reviewed before any work starts. Matan reviews it: at least one comment on a specific line, Claude
replies and fixes it with a new commit, Matan reviews again and resolves the conversation.
